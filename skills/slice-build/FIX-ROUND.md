# After verify

The one fix round of a verify run. The steps (a) to (g) and After the last slice are in [SKILL.md](SKILL.md).

When verify reports findings, the session that ran verify loads this skill for one fix round. You orchestrate it as you do a slice: fresh writers do the work, you make the commits, and When a step fails ([FAILURES.md](FAILURES.md)) applies, except for Bugs left: in this round every bug on that line goes to the owner (below), never to a fix slice.

`<default branch>` in this round is the `Base:` branch of the verify report that started it. First read the trailers as [CHECKS.md](CHECKS.md), Resume, says. When the working branch ends in a tests commit with the value `verify`, an earlier fix round stopped after its tests commit: put it to the owner as one question in the form of the `idea-to-code:grilling` skill, before you sort a finding.

1. Sort every finding into one route:
   - **Fix:** it cites something written: an unticked task, a requirement or scenario not met, a behaviour nobody asked for, or a breach of a written repo standard. A failure of the test command or of the check command at verify is a Fix finding, unless it is a base failure (Owner, below).
   - **Test first:** a Fix finding that needs a test changed or added before the code.
   - **Owner:** it needs a spec change, or it is unasked behaviour you judge worth keeping. Put each to the owner as one question in the form of the `idea-to-code:grilling` skill before the code writer starts; an answer that asks for a fix moves the finding to Fix. An answer that keeps unasked behaviour: write the behaviour into the change's delta spec (in a repo without specs, into `design.md`), so the second verify finds it asked for, and close the finding. An answer that changes the spec: write the change the same way, then route the finding to Test first (to Fix in a repo without specs). The round's first commit (step 2, else step 5) carries each spec edit. A failure of the test command that the check of A failure that the default branch has too ([CHECKS.md](CHECKS.md)) shows as a base failure, and that no `base` record answers, is an Owner finding: put it to the owner as that section says. The answer Fix it in this change moves it to Fix. The answer Keep it out closes it, and its record line goes under `### Answers` (step 6). A test-lock finding of verify is an Owner finding, and no route of this round removes its commit: it stays on the working branch, because the flow never amends. Only the owner's answer clears it. Put one question per offending commit to the owner, as [CHECKS.md](CHECKS.md) says under Test lock at verify, and write each answer as a record line in `build-report.md` (step 6), with the kind `lock`. The answer to keep the edit closes the finding. The answer to restore the test needs no writer: you bring back each test file of the commit, one path at a time: `git checkout <hash>^ -- <path>` for an M or D line and for the first path of an R line, and `git rm <path>` for an A line and for the second path of an R line. First run `git log --format=%h <hash>..HEAD -- <paths>`. When it prints a line, a later commit changed one of those files, and the checkout would undo that change too: restore nothing, and put it to the owner as one question in the form of the `idea-to-code:grilling` skill. Otherwise commit the restored files as a tests commit with `Tests-For: verify`, by the command of (d), with no red check. Then run the test command. When a restored test fails, it goes to step 3 as a Fix finding, and steps 3 to 5 run. An uncommitted test-file change is never answered away: put it to the owner as one question: you commit it as a tests commit with `Tests-For: verify`, by the command of (d), or the owner removes it. Discard nothing yourself, and start no code writer while it is in the tree: a failed check (f) would remove it. The round's report names each commit, the answer and the record.
   - **Past commit:** it is about a commit already made, and no code can fix it, because the flow never amends: the commit message breaks a commit rule of the repo (verify finds it, see its step 5). Put one question per commit to the owner, in the form of the `idea-to-code:grilling` skill, before the code writer starts: the finding, the commit (hash and title), and two options. **Keep it as it is** (the commit stays). **Stop** (the finding stays open and the round writes no record for it). No option offers a fix, because the flow never amends. The question is still asked: the session never records Keep by its own choice. Recommend one option, and give the basis. With findings on several commits, ask one question after the other, never in one message. The answer to keep closes the finding. Write each answer as a record line in `build-report.md` (step 6), in the form that [CHECKS.md](CHECKS.md) gives under Answers in the build report. Write it only for the owner's answer to this question, never before it and never in its place. A later verify lists that commit as answered, and it is no finding.
   - **Lead:** a smell with no cited rule. It is a lead for the owner, not a fix: list it in the report.

   When no finding is routed to Fix or Test first, skip steps 2 to 4. In step 5, commit only the spec edits of the Owner answers, and skip the step when there are none.
2. For the Test first findings, start one fresh test writer with them ([BRIEFS.md](BRIEFS.md)). Run the red check (c) on its tests by hand ([CHECKS.md](CHECKS.md), Red check) and commit them as in (d), with the trailer `Tests-For: verify`.
3. Start one fresh code writer with every Fix and Test first finding ([BRIEFS.md](BRIEFS.md)), and with the diff command of the change, `git diff <default branch>...HEAD`. It fixes each finding at every place of that diff that breaks the same rule or holds the same stale text, not only at the place that the finding names. The test files are locked at the commit it starts from.
4. Run the test-file check (f) against that commit, by hand ([CHECKS.md](CHECKS.md), Test lock). The test check script does not run in this round: it compares the tests with one slice's tests commit.
5. Run the repo's full test command; it passes. A base failure that the owner answered with Keep it out does not count. Tick each task box the fix completes. Load the `idea-to-code:commit` skill and commit the fix.
6. Append the round's report (below) to `build-report.md` in the change folder, under the heading `## Fix round`. Create the file when it is missing. Put each record line of an owner's answer on an offending commit, on a past commit or on a base failure under `### Answers` in that section, in the form that [CHECKS.md](CHECKS.md) gives. Write the record line even when the round has no other finding, and only for the owner's answer to that question: never before it, and never in its place. Commit that file alone, as After the last slice says for the build report, a failed check command included. Then run verify once more, as the `/idea-to-code:verify` command says: steps 3 to 7, and write that pass's report as text (its `Verify rules:` line and its `Base:` line first) before the result gate.

In a repo without specs, skip steps 2 and 4, and put a finding that needs a test change to the owner.

One round per verify run, apart from a round that the owner's answer at the result gate starts (`idea-to-code:owner-gate`). A later verify run starts a round of its own, which appends its own `## Fix round` section to `build-report.md`; the records of every section count. A finding that the owner answered with Stop has no record, so it is asked again. A finding still open after it goes to the owner as one question in the form of the `idea-to-code:grilling` skill, and so does a bug the code writer listed under Bugs left. A finding still open means verify has not passed.

Report to the owner: each finding with its route and outcome, each offending commit and each past commit with the owner's answer, the round's commits, every question put to the owner, every lead, and the `Project rules:` line and the `Check command:` line that the `idea-to-code:commit` skill gave at the commit of step 5.

Done when the second verify passes, or every finding still open is with the owner.
